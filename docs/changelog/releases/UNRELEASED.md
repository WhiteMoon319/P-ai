## 修复
- 修复（tools）：`read_media` 按图片、音频、视频设置分级解析时限，超时后以正常工具结果返回“解析超时”，避免远程应答委托长期停留在运行中。
- 修复（remote-im）：秘书助理工作账本仅注入当前活跃的远程应答委托，不再携带历史已完成或失败委托，避免长期会话提示词持续膨胀并干扰新消息判断。
- 修复（chat）：追问标签切换改为右侧面板独占订阅槽，旧标签后端解绑完成后才允许新标签建立 Channel，并补齐恢复期间再次触发时的最新状态重跑。
- 修复（chat）：补齐追问会话的运行态、消息追加与异步补消息同步，统一权威快照、Channel 探针和目标消息恢复，并修复主会话切换时追问视图卸载导致的 VNode 异常。
- 修复（sidebar）：修复 Web/移动端切回前台后流式会话卡住，统一沿用前台恢复状态判定，优先恢复订阅与目标消息投影，避免无必要的整页刷新。
- 修复（chat）：修复应用启动后新会话首条消息的 assistant 气泡可能缺失，确保提交通道、调度增量与正式消息终态可靠对账。
- 修复（remote-im）：远程联系人列表与设置页的入场方式收口为前端单项下拉，私聊仅显示并默认固定为“始终入场”，避免旧状态在 UI 中继续露出“不入场/关键词入场”。
- 修复（remote-im）：秘书判断最大超时收口为 60 秒，且判断失败或超时统一视为不回复，不再走失败后始终回复的兜底。
- 修复（remote-im）：远程应答委托仅在确有并行处理中消息时注入忙碌提示，并保留原始发送者昵称，避免同一话题重复回答或误把联系人 ID 当作发言人。
- 修复（remote-im）：固定后续应答委托的处理中提醒位于最新消息 metadata 之前，避免两轮消息组装后模型优先看到错误的消息顺序。

## 重构
- 重构（chat）：主会话与当前追问会话共用同一套权威快照绑定事务、前台 runtime/probe/freshness 恢复协调和正式消息归约规则，并为连续切换与前台触发统一 latest-wins 执行。
- 重构（chat）：活动流绑定增加 ConversationView 实例 ID，同一窗口可为不同会话维护独立 Channel；全局轮次事件改为按 conversationId 查找已注册 chat flow，为双会话并行流式预留统一通信底座。
