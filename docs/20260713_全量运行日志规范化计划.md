# 全量运行日志规范化计划

## 目标

统一 Rust 与前端运行日志的等级、中文文案、状态表达和排障字段，消除 `eprintln!` 被统一记为 info 导致的等级失真，并建立可重复审计能力。

## 范围

- `src-tauri/src/` 中的 `runtime_log_*` 与 `eprintln!`
- `src/` 中的 `console.error/warn/info/debug/log`
- 排除注释、字符串、测试 Markdown 代码块和宏定义中的伪调用

## 实施方式

1. 扫描源码并生成独立 JSON 索引，记录顺序、文件、源码跨度、原文和哈希。
2. 生成 TXT，每条日志严格占一行，仅包含日志代码，不附加 ID、路径或说明。
3. 逐条修正 TXT 中的日志等级与文案。
4. 回填前校验索引数量、文件哈希、原文哈希、日志顺序和非空行。
5. 在内存中执行替换后重新扫描，再反向替换并比较原始文件哈希，确认过程可逆。
6. 正式写入使用临时文件替换；任一文件失败则不写入该文件。

## 等级原则

- error：操作失败或非预期异常，必须携带异常信息。
- warn：降级、兜底、跳过、重试和可恢复异常。
- info：正常流程节点、服务状态切换和用户可见行为变化。
- debug：变量、参数、缓存、快照、诊断和高频明细。
- trace：仅保留明确执行追踪，使用 `[TRACE]` 前缀。

## 验证

- 导出 TXT 行数与索引数量一致。
- dry-run 和反向还原哈希通过。
- 不再存在非 info 语义的 `eprintln!`。
- `cargo check` 通过。
- `pnpm typecheck` 通过。
- 审计脚本复扫并输出剩余人工复核项。

## 回滚

回填前保留索引中的完整原文；工具支持根据索引反向恢复。正式修改同时由 Git 提供文件级回滚能力，不使用破坏性 Git 命令。
