# 助理消息统一内容块重构计划

## 目标

将助理消息的后端运行缓存、传输数据、前端运行缓存和持久化结果统一为同一份内容块结构，禁止完成时重建、替换或反向推导正文。

## 核心约束

1. `AssistantStreamBlock[]` 升级为助理消息的正式内容结构，不再是临时流式字段。
2. 后端缓存、事件快照、前端缓存、持久化和历史加载使用同一字段和同一序列化语义。
3. 消息完成只修改状态，不修改内容块。
4. 已存在同 ID 消息时，完成快照不追加、不替换、不合并正文；只在本地完全缺少该 ID 时追加整条消息。
5. 撤回/截断保持独立授权链路，普通同步不得删除已显示消息。

## 实施步骤

1. 在 Rust/TypeScript 消息类型中增加正式内容块字段，对齐命名、默认值和 serde 字段。
2. 后端流式运行缓存直接更新该字段，持久化时原样写入消息，不再另行合并正文。
3. 流式事件传输同一内容块快照；前端仅接收该快照，删除独立重放导致分叉的 reducer 路径。
4. 前端流式、完成态和历史加载统一从内容块渲染，移除从 `parts + toolCall` 重建助理正文的路径。
5. 对旧消息执行单向兼容读取：缺少内容块时构建一次，新数据只写统一结构，不长期双写。
6. 收口上一提交中的追加式账本，避免它与正式内容块形成第二份事实源。

## 验证

1. Rust 定向测试：同一事件序列在运行缓存和持久化消息中的内容块完全相等。
2. 前端定向测试：流式、完成、全新加载的渲染输入完全相等。
3. 同 ID 完成快照不改动现有消息；缺少 ID 时才追加。
4. 工具调用前后正文、reasoning、Markdown 和内容块边界在三种状态下一致。
5. 运行最小相关 Vitest、Rust 定向测试、`pnpm typecheck` 和 `cargo check`。
