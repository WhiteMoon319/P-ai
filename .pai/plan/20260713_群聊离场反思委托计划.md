# 20260713_群聊离场反思委托计划

## 用户原始关键指令

> "我们远程联系人，因为启动的时候的压缩有时间紧迫性，所以不能进行反思，那么我们是否可以在离场的时候进行反思？新增一个群聊的离场反思，提示词跟归档反思一样的就行，目的是为了让LLM生成记忆，可以复用归档反思，但是只取记忆"
>
> "离场的时候直接那离场的时候的上下文不就行了吗？入场的时候已经裁剪过一次了。 就直接以这个上下文让LLM去反思"
>
> "直接远程联系人的负责部门人格，启动一个反思委托，让他输出json然后生成记忆。 清理本次在场上下文是没有意义的，因为重新入场的时候会重新整理"
>
> "请注意，这个反思委托也要进入委托看板哦"

## 一、目标

在远程群聊联系人离场后，由该联系人的负责部门人格执行一次独立的离场反思委托，复用归档反思的记忆整理规则，根据离场时已有上下文生成并应用记忆，同时在委托看板中完整展示该委托的执行状态。

## 二、需求描述

### 2.1 触发场景

- 仅远程群聊联系人发生真实离场时触发离场反思。
- 私聊联系人不触发群聊离场反思。
- 过期离场判断、重复离场通知或联系人仍处于在场状态时不得重复发起反思委托。
- 离场状态本身不等待反思结果；反思成功或失败均不影响联系人完成离场，也不阻止联系人再次入场。

### 2.2 反思委托归属

- 离场反思使用该远程联系人当前绑定的负责部门与负责人格。
- 反思委托归属于该远程联系人绑定的会话，能够在该会话的委托看板中查看。
- 委托看板应展示反思委托的运行中、完成、失败和被打断状态，并允许进入委托详情查看执行记录。
- 离场反思使用独立且可识别的委托类型和标题，不与普通远程应答委托混淆。

### 2.3 反思上下文

- 反思直接使用联系人离场时已经存在的上下文。
- 入场时已经完成的上下文整理结果应被直接复用，不为离场反思重新读取、重新裁剪或重新压缩完整会话。
- 离场反思看到的上下文应包含离场时可见的用户发言、助理回答和必要的记忆回灌内容；反思启动期间新落库的消息允许一并参与反思，不要求按离场瞬间严格截断。
- 反思完成后不清理本次在场上下文；联系人重新入场时继续沿用现有的重新整理行为。

### 2.4 反思输出

- 反思提示要求与归档反思保持一致，以合法 JSON 输出记忆整理结果。
- 系统只消费 `usefulMemoryIds` 与 `memoryActions`。
- 不消费或保存会话标题、摘要、开放待办等归档结果。
- 反思委托不得调用工具，不得向远程联系人发送消息，也不得把 JSON 作为普通助理回答写回联系人会话。

### 2.5 记忆生成

- 合法反思结果应按现有记忆规则处理仍有用的旧记忆以及新增、修正、合并记忆。
- 记忆必须归属于执行反思的负责人格，并遵守该人格的私有记忆设置和可见范围。
- JSON 无效、模型请求失败或记忆写入失败时，本次委托标记为失败并保留可排障信息，不得应用部分不可信结果。
- 同一次离场反思的记忆结果只能应用一次，避免重试、重复通知或状态恢复造成重复记忆。

### 2.6 用户可见行为

- 离场反思不向联系人发送任何提示。
- 离场反思不向当前助理追加完成通知或普通聊天消息。
- 用户可通过委托看板观察反思是否运行、完成、失败或被打断，并查看对应委托详情。

## 三、风险

### 3.1 重复反思与重复记忆

同一离场事件可能受到多个延迟判断或重试影响。必须保证一次真实离场只产生一次有效反思，并且记忆结果只应用一次。

### 3.2 应答尚未完成时提前离场

离场定时器到期时，应答委托可能仍在生成回复。此时不得离场或启动反思；应答委托结束后重新安排离场计时，确保反思能够看到已经完成的回答。

### 3.3 群成员信息混淆

群聊包含多名成员，模型可能把不同成员的信息错误合并。反思必须保留上下文中的联系人身份信息，并遵守现有记忆生成规则，避免把不同群成员当成同一人。

### 3.4 后台模型资源竞争

多个群聊接近同时离场时可能集中产生反思委托。反思不得阻塞联系人状态变化和正常应答，且应遵守现有模型供应商并发限制。

### 3.5 看板状态与实际执行不一致

若反思执行、JSON 解析或记忆应用失败，但委托仍显示成功，会造成错误判断。委托最终状态必须以记忆处理链路的实际结果为准。

### 3.6 联系人配置变化

离场后联系人绑定部门或人格可能发生变化。反思委托应保持发起时确定的负责部门和人格，不因后续配置变化转移归属。

## 四、边界

### 做

- 远程群聊真实离场时发起记忆反思委托。
- 使用离场时已有上下文和联系人负责部门人格。
- 复用归档反思的记忆输出口径，只处理记忆相关字段。
- 将反思委托纳入当前会话委托看板和委托详情。
- 支持成功、失败、打断和重复触发保护。

### 不做

- 不在群聊入场压缩阶段执行反思。
- 不为离场反思重新整读、裁剪或压缩完整联系人会话。
- 不清理本次在场上下文。
- 不修改联系人重新入场时的上下文整理行为。
- 不为私聊联系人增加离场反思。
- 不生成或保存归档摘要、标题、开放待办。
- 不自动向联系人或普通聊天会话发送反思结果。
- 不新增用户手动选择反思模型的交互。

### 前提

- 远程群聊联系人已经绑定可用的负责部门和负责人格。
- 离场时能够取得本次已整理的有效上下文。
- 负责人格存在可用的文本对话模型配置。
- 现有记忆规则、反思 JSON 解析和委托看板可继续作为统一基础能力。

## 五、统一口径

- 功能名称统一使用“群聊离场反思”。
- 委托名称统一使用“离场反思委托”。
- 委托类型应与普通“远程应答委托”明确区分。
- 日志前缀统一使用 `[群聊离场反思]`。
- 状态文案统一使用：`开始`、`完成`、`跳过`、`失败`、`打断`。
- “离场时已有上下文”指联系人完成本次在场过程后、触发离场时可供模型使用的现有上下文，不表示重新构造的归档上下文。
- “只取记忆”统一指只消费 `usefulMemoryIds` 和 `memoryActions`。

## 六、术语解释

- **负责部门人格**：远程联系人当前绑定并负责处理该联系人消息的部门与人格组合。
- **离场**：远程群聊联系人从在场状态转换为离场状态的有效状态变化。
- **离场反思委托**：联系人离场后发起、只负责输出记忆整理 JSON 的内部委托。
- **离场时已有上下文**：本次入场整理后持续用于远程群聊处理，并在离场时可直接提供给反思模型的上下文。
- **委托看板**：当前会话中展示委托运行状态、执行信息和详情入口的用户界面。
- **记忆整理结果**：归档反思 JSON 中的 `usefulMemoryIds` 与 `memoryActions`。

## 七、应该有的测试

### 核心链路测试（必须）

- 群聊从在场转换为离场时，创建一个归属于当前联系人会话的离场反思委托。
- 委托使用联系人负责部门和负责人格，并使用离场时已有上下文。
- 合法 JSON 结果只应用 `usefulMemoryIds` 与 `memoryActions`，不生成归档摘要或聊天回复。
- 离场反思委托能够出现在当前会话委托看板，并正确展示运行中与最终状态。

### 边界条件测试（必须）

- 私聊离场不创建群聊离场反思委托。
- 过期离场判断和重复离场通知不创建重复委托。
- 上下文为空、负责部门人格不可用或模型不可用时安全跳过或失败，并保留明确原因。
- JSON 无效、模型失败、记忆写入失败时不得应用部分结果，委托状态为失败。
- 同一反思结果重复到达时不得重复写入记忆。
- 联系人反思期间重新入场，不影响新一轮入场和正常应答。

### 回归测试

- 原有远程应答委托创建、执行、看板展示和打断行为保持不变。
- 原有归档反思的提示词、JSON 解析与记忆写入行为保持不变。
- 原有群聊离场状态转换与耐心超时判断保持不变。
- 原有入场上下文整理不因离场反思而增加等待时间。

### 集成验证

- 完成一轮包含群成员发言、助理回答和记忆回灌的群聊，在离场后观察委托看板出现离场反思委托，并确认成功后生成预期记忆。
- 人为制造无效 JSON 或模型失败，确认联系人仍正常离场、看板显示失败且下一次入场不受影响。

## 八、最终呈现结果

```text
远程群聊完成本次在场过程
→ 联系人离场
→ 当前会话委托看板出现“群聊离场反思”委托
→ 负责部门人格根据离场时已有上下文输出记忆 JSON
→ 系统只应用 usefulMemoryIds / memoryActions
→ 委托看板显示完成或失败
→ 不向联系人或普通聊天正文发送反思结果
```
