# 图像编辑工具与多图融合支持计划

## 目标

在现有独立图像生成模块中补齐图像编辑能力，新增面向 LLM 的 `image_edit` 工具，支持：

- 局部修改、局部重绘、对象消除、背景替换与扩图（inpainting/outpainting）。
- 多图融合、主体/风格参考与组合场景生成。
- 与现有 `image_generate` 共用默认生图模型、供应商配置、API Key 和 Codex 登录态。
- 不新增独立的图像编辑供应商页，不让用户填写工程参数；输入图像、mask 和编辑意图由 LLM 根据对话附件自动组织。

## 设计决策

### 工具边界

- 保留现有 `image_generate`：纯文本到图像，只要求 `prompt`。
- 新增 `image_edit`：图像到图像，参数由 LLM 填写：
  - `prompt`：编辑/融合意图。
  - `images`：一张或多张对话附件引用；优先使用内部附件引用，兼容已有的本地文件或 data URL 表达。
  - `mask`：可选 mask 附件，仅在供应商/工作流支持时发送。
  - `aspect_ratio`：仅多图融合或 outpaint 在确有需要时由 LLM 提供；不在设置页暴露。
- 不把 `model_id`、供应商、质量、steps、seed、negative prompt、数量等暴露给 LLM 或用户；默认模型继续来自设置页“对话”选项卡。

### 统一请求模型

扩展图像生成模块内部请求类型，保留同一 Tauri 命令和统一结果格式；通过 `operation=generate|edit` 与输入图像集合区分路径。编辑工具调用同一服务入口，供应商适配层负责把内部输入转换为各自协议。

### 供应商适配策略

1. OpenAI：优先走 `/v1/images/edits` multipart；支持 `image[]` 与可选 `mask`，对 GPT Image 2 遵循其当前不需要显式 `input_fidelity` 的规则。
2. xAI：走 JSON `/v1/images/edits`；单图 `image`，多图 `images`，输入使用 data URL 或 file ID；不发送未被官方确认的 mask 字段。
3. Seedream：按当前模型版本的官方请求 schema 实现单图/多图图生图；5.0 Pro 的交互编辑能力单独适配，未确认的 mask 字段先不伪造。
4. Gemini：把附件转成 `inlineData`/`fileData` 多模态内容，文本作为编辑指令；支持最多 14 张参考图的限制校验。
5. ComfyUI：将编辑输入注入配置的 workflow JSON；定义明确的输入节点映射（原图、mask、提示词、尺寸），无法映射时返回可读错误，不静默按文本生图降级。
6. Codex：复用现有 Codex 认证；按照官方 image edit API 能力接入输入图与 mask，认证失败仍走现有统一归因链路。

## 实施阶段

1. **协议与工具 schema**
   - 新增 `image_edit` 元数据、JSON schema、工具注册、工具策略与超时。
   - 建立对话附件到工具输入的最小引用解析，避免读取完整历史消息。

2. **后端请求与供应商适配**
   - 扩展内部请求/结果类型。
   - 先实现 OpenAI、xAI、Codex、Gemini、Seedream 的编辑/多图 payload。
   - 为 ComfyUI 增加 workflow 输入映射和 inpaint/outpaint 错误边界。

3. **存储与返回**
   - 复用现有图片下载、持久化、Markdown 图片地址和对话展示链路。
   - 编辑结果与生成结果使用相同资产格式，保留供应商返回 URL（如果有）。

4. **设置与测试入口**
   - 不新建图像编辑设置页，不增加工程参数卡。
   - 现有生图测试仍只提供提示词；编辑能力通过对话附件和 LLM 工具调用验证。

5. **测试与验证**
   - 单元测试：工具 schema、附件引用、mask 可选性、单图/多图 payload、供应商能力限制。
   - 集成测试：OpenAI/xAI/Gemini/Seedream mock 响应、Codex 登录态复用、ComfyUI workflow 输入映射。
   - 回归检查：纯文本 `image_generate` 行为不变；编辑失败不能错误返回“已生成”。

## 明确不做

- 不新增第二套 API Key 或 Codex 登录流程。
- 不新增独立“图像编辑模型”设置页或聊天输入面板下拉框。
- 不把供应商私有工程参数变成用户配置项。
- 不承诺所有供应商都支持同样的 mask 语义；能力差异由适配层和错误提示明确表达。

## 验收标准

- LLM 能自动区分文本生图和图像编辑，并在编辑请求中使用对话附件。
- 单图局部修改、带 mask 的 OpenAI/Codex 编辑、xAI/Gemini/Seedream 多图融合、ComfyUI inpaint 工作流均有可验证路径。
- 生成与编辑结果都返回可直接展示的本地图片地址/Markdown。
- 设置页布局和现有供应商/模型模板不被新增编辑配置破坏。
