# 20260713_远程联系人助理工作账本计划

## 用户原始关键指令

> 接下来我们需要建立远程联系人统一内存账本，在远程应答开始，完成/失败的时候更新。
>
> 然后在回复判定和反思的时候共用这个账本，统一生成，助理工作账本

## 一、目标

建立远程联系人统一的助理工作账本，让回复判定、应答委托和离场反思使用同一份工作状态与结果口径，避免从聊天消息或不同运行时状态重复推导。

## 二、需求描述

### 2.1 统一账本

- 为远程联系人生成统一的助理工作账本。
- 账本能够识别具体应答委托、所属会话、触发消息、负责部门与人格、任务状态和结果。
- 同一份账本同时表达运行中、已完成和失败的应答工作。

### 2.2 生命周期更新

- 远程应答委托开始时，账本出现运行中记录。
- 远程应答委托完成时，账本更新为完成并包含结果摘要。
- 远程应答委托失败或中止时，账本更新为失败并包含原因。
- 后续消息被送入已有应答委托时，账本能够反映该委托正在处理的工作范围。

### 2.3 共用范围

- 秘书回复判定使用助理工作账本判断是否需要回复以及应引导到哪个委托。
- 新建远程应答委托的系统提醒使用同一助理工作账本，避免重复处理。
- 群聊离场反思使用同一助理工作账本理解本次在场期间的助理工作。

## 三、风险

- **状态失配**：生命周期更新遗漏会导致账本与真实委托状态不一致；账本应以正式委托记录为准并在终态统一收口。
- **并发覆盖**：同一联系人可能同时存在多个应答委托；账本必须按委托 ID 区分，不能使用单一联系人状态互相覆盖。
- **上下文膨胀**：历史工作过多会增加提示词长度；输出需要限制数量并截断摘要。
- **重启恢复**：应用退出时运行中委托会被恢复为失败；恢复后的账本必须显示正式失败终态，不能永久显示运行中。
- **隐私串线**：不同联系人或会话的工作不能混入；生成账本时必须按联系人归属过滤，并保留会话标识用于核对。

## 四、边界

- **做**：远程应答委托的开始、完成、失败、中止和引导消息范围；回复判定、应答提醒、离场反思共用账本。
- **不做**：普通聊天委托、任务委托和其他非远程应答委托的统一账本；新增账本管理 UI；改变秘书的 `targetDelegateId` 路由协议。
- **前提**：应答工作以正式远程应答委托为唯一身份，委托 ID 是运行中工作路由和账本关联的唯一标识。

## 五、统一口径

- 统一名称使用“助理工作账本”。
- 工作状态统一使用“运行中”“已完成”“失败”。
- 回复判定和应答系统提醒中必须显示委托 ID，便于 `targetDelegateId` 精确路由。
- 账本生成失败时记录告警并降级为空账本，不阻断远程消息接入、应答或离场反思。

## 六、术语解释

- **助理工作账本**：按远程联系人汇总的应答委托工作投影，包含委托身份、任务范围、状态与结果。
- **工作记录**：账本中对应一个远程应答委托的独立条目。
- **结果摘要**：应答委托完成后的实际回复摘要，或失败时的原因摘要。
- **引导消息**：秘书通过 `targetDelegateId` 追加给运行中应答委托的后续消息。

## 七、应该有的测试

- 核心：运行中应答委托能够生成带委托 ID、触发消息摘要和运行状态的账本记录。
- 核心：完成和失败委托分别生成正确终态与结果摘要。
- 核心：回复判定、应答系统提醒和离场反思使用同一个账本生成入口。
- 边界：同一联系人多个并发委托不会互相覆盖。
- 边界：其他联系人和非远程应答委托不会进入账本。
- 边界：账本读取失败时不阻断原业务链路。
- 回归：秘书仍能通过 `targetDelegateId` 引导现有应答委托。
- 回归：离场反思仍只应用记忆相关 JSON 结果。

## 八、最终呈现结果

```text
助理工作账本：
- [运行中] 委托 ID：...；任务：...；开始：...
- [已完成] 委托 ID：...；任务：...；结果：...
- [失败] 委托 ID：...；任务：...；原因：...
```
