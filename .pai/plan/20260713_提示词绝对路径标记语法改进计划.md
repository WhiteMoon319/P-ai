# 20260713_提示词绝对路径标记语法改进计划

## 用户原始关键指令

> "我们有一个提示词是这样描述的，LLM老以为这是路径，实际上想说的这里需要绝对路径，这里写法完全不恰当"
>
> "我们换成[file.rs](|{{absolute_path}}/file.rs) 会不会更好？"
>
> "{{absolute_path}} 是提示词里给 LLM 看的字面量，不是给代码处理的模板变量"
>
> "到底要怎么写才能让LLM知道，这里填的是绝对路径"

## 一、目标

改进提示词中本地文件引用的标记语法，消除 LLM 将提示词示例路径误认为真实路径的问题。

## 二、需求描述

### 2.1 问题

当前提示词（`interface_local_conversation.md`）教导 LLM 使用 Markdown 链接语法来表示本地文件引用：

```
- 本地文件：[file.rs](/abs/path/file.rs)
- 本地文件带行号：[file.rs](/abs/path/file.rs:12)
- 本地图片：![结果图](E:/path/to/result.png)
```

LLM 看到 `/abs/path/file.rs` 会误认为这是一个真实存在的文件路径，而不是"此处需要填入绝对路径"的指示。

### 2.2 解决方案

保持最终输出为前端已经支持的标准 Markdown，不引入 `|{{absolute_path}}` 等自定义路径协议。使用大写语法占位符，并明确要求模型在输出时完整替换：

- 文件：`[文件名](ABSOLUTE_FILE_PATH)`
- 文件带行号：`[文件名](ABSOLUTE_FILE_PATH:LINE)`
- 图片：`![说明](ABSOLUTE_IMAGE_PATH)`

关键设计：
- `ABSOLUTE_FILE_PATH`、`ABSOLUTE_IMAGE_PATH`、`LINE` 只用于解释语法，禁止原样输出
- 最终链接目标必须是真实绝对路径，不得使用相对路径
- 同时给出 Windows 盘符、UNC、Linux/macOS 绝对路径规则和正反例
- 路径包含空格时使用 CommonMark 尖括号目标，例如 `[My File.rs](<C:/My Project/src/My File.rs:12>)`

| 文件 | 改动 |

| `src-tauri/resources/prompts/interface_local_conversation.md` | 替换第 12-13、19 行中的文件引用示例语法 |

### 2.4 统一口径

所有教 LLM 在聊天正文中输出本地 Markdown 链接或图片的地方，统一使用大写语法占位符，并明确要求替换为真实绝对路径。工具参数中“传入绝对路径”的描述保持不变，因为它们要求的本来就是真实参数值，不属于 Markdown 示例问题。

## 三、最终呈现结果

### 改动前（LLM 收到的指令）

```
- 本地文件：[file.rs](/abs/path/file.rs)
- 本地文件带行号：[file.rs](/abs/path/file.rs:12)
- 本地图片：![结果图](E:/path/to/result.png)
```

### 改动后

```
- 本地文件格式：`[文件名](ABSOLUTE_FILE_PATH)`
- 本地文件带行号格式：`[文件名](ABSOLUTE_FILE_PATH:LINE)`
- 本地图片格式：`![说明](ABSOLUTE_IMAGE_PATH)`
```

### 配套文案说明

配套文案必须说明占位符不得原样输出，并给出真实绝对路径形式的正例与相对路径反例。路径包含空格时说明使用尖括号包裹链接目标。

## 四、验证

- 搜索确认旧的 `/abs/path/file.rs`、`![说明](本地路径)`、`![description](local/path.png)` 已从相关提示词移除
- 搜索确认未引入被否决的 `|{{absolute_path}}`
- 本次只改 Markdown 教学文案，不修改渲染器或解析器，不新增逐字断言提示词的单元测试
